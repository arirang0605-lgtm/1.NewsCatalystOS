# NewsCatalystOS 실사용 운영 기준 — 2026-10-15

사용자 요청: “전 개발에서 운영규칙을 보수적으로 만든 경향이 있어 너가 운영에 딱 필요한 수준으로 정리해줘.” D-059는 아래 필수·선택 구분을 적용한 구현 결정이다. 이전 D-058(모든 뉴스 기사 별도 사람 검수 제외)을 포함하며, 과거 명세·마스터 프롬프트의 상충하는 승인·출시 대기 규칙보다 우선한다.

## 운영 시작에 필요한 것

1. 기존 36개 기능의 핵심 경로가 구현되어 있고, 실제 수집→분석→저장→조회가 한 번 이상 성공한다. 수집 성공만으로 전체 처리 성공을 대신하지 않는다.
2. AI 제공자의 실제 생성 응답·사용량·비용을 한 번 이상 확인한다. 이미 수집한 기사로 연결을 확인해도 된다. 과거 기사는 과거 기사로 표시하고 새 사건으로 세지 않는다. 새 대형 사건이 나올 때까지 연결 개발을 중단할 필요는 없다.
3. 출처 URL·수집시각·원문 또는 제목 근거를 남긴다. 숫자는 출처와 연결하고 AI 해석은 보도 내용과 구별한다. 기사마다 사람 검수·독립 사실 인증은 요구하지 않는다. 자료가 부족한 항목은 미확인 표시 후 다른 처리를 계속한다.
4. 키·운영 DB·원문은 비공개로 보관한다. 기존 월 5만원 AI 한도와 호출 예약·캐시·중복 방지를 적용한다. 사용자가 승인한 범위의 실행을 매번 재승인받지 않는다. 예산 상향은 별도 설정 변경이며 이번 정리에서 금액을 변경하지 않는다.
5. 운영 DB를 백업하고 별도 폴더에 복원하여 읽을 수 있는지 확인한다. 같은 장치의 별도 폴더 복원으로 시작할 수 있다. 원본 덮어쓰기는 금지한다.
6. 수집·분석 실패를 기록하고 재시도 가능하게 한다. 미해결 P0/P1 장애와 회귀 시험 실패가 없어야 한다. 개발 중에는 변경 영향 시험, 통합 출시 시에는 전체 회귀를 실행한다. 같은 상태의 시험을 반복하지 않는다.

## 운영을 시작한 뒤 관찰하거나 선택하는 것

- **5거래일:** 출시 차단 조건에서 운영 후 안정성 관찰 목표로 전환한다. 수집 일수와 거래일 수를 구분하여 실제 기록만 표시한다. 별도 거래소 달력 인증자·서명은 요구하지 않는다. 달력이 없으면 수집 날짜를 그대로 보여 준다.
- **뉴스 검수:** 2명·500건 정답·정확도 인증은 필수가 아니다. 기존 Gold 도구는 선택적 연구용으로 보존하며 기본 예약 실행에서 제외한다. 연구 실패는 뉴스 수집·분석 실패가 아니다.
- **백업:** 별도 물리 장치·원거리 백업은 권장 사항이다. 독립 장치 검증은 운영 시작을 막지 않는다.
- **EraLeader:** 기존 공유 자료는 읽기 전용으로 사용한다. 외부 소비자 실연동이 없으면 해당 연동만 대기하며 NewsCatalystOS 자체 운영은 진행한다.
- **추가 인증:** 출처별 다중 SHA/PIN, 독립 프로세스 서명, 기관 발행시각 공증은 필요한 특수 경로에서만 사용한다. 기존 무결성·시점 기록을 삭제하거나 소급하지 않으며 일반 기사 분석에 추가 절차를 만들지 않는다.

## 코드와 실행

- `release_readiness.py`: 필수 항목을 만족하면 `operation_ready=true`, `status=READY_FOR_OPERATION`으로 통과한다. 5거래일·외부 연동·별도 장치 항목은 `follow_ups`로 표시한다. 독립 인증 여부는 별도 정보이며 통과를 막지 않는다.
- `PYTHONPATH=src python3 scripts/check_v1_release.py --evidence /절대경로/실행결과.json`: `ReadinessInputs` 필드의 실제 실행 결과를 읽는다. 통과는 종료코드 0, 부족·오류는 4. 입력 결과 평가이며 파일 자체의 진위 인증이나 자동 태그·배포는 아니다. 테스트 fixture를 운영 증거로 입력하지 않는다.
- 필요한 입력: `completed_tasks`, `successful_pipeline_runs`, `numeric_claim_source_linkage`, `real_ai_provider_calls`, `actual_ai_month_cost_krw`, `backup_restore_verified`(기존 물리 복원 성공도 인정), `full_regression_tests_passed`, `full_regression_tests_failed`, `unresolved_p0_p1`.
- 예약 AI는 기존 `run_scheduled_triage.py` 또는 `run_motir_policy_once.py`에 `--analysis-model-config /비공개/모델설정.json --allow-paid-ai`를 한 번 설정한다. 중요 신규 사건 자동 분석에 기존 예산·캐시를 사용한다. 모델 설정·키가 없으면 해당 AI 경로를 미설정으로 표시한다. dry-run·replay-only에서는 유료 호출하지 않는다.
- 예약 실행 요약의 `new_ai_results`는 성공 결과 수다. 실제 HTTP 호출·비용은 비용 원장에서 확인하며, 유료 모드의 요약 `ai_call_count=null`은 0회라는 뜻이 아니다.
