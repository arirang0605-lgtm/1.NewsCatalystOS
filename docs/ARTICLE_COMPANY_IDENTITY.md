# 기존 공시 명부 → 기사 속 기업 식별

## 실제 기능

`official_filing_context.read_pinned_filing_context`로 기존 완료 DART/SEC 원본·영수증·독립 pin을 읽고, 기사 원문 이름을 해당 명부의 기업명/법인코드에 연결한다. 원본 수집 API, EraLeader 코드/DB/설정은 변경하지 않는다.

- 같은 정규화 이름에 법인 식별자가 하나일 때만 연결한다. 여러 공시는 중복 기업으로 세지 않는다.
- 동일 이름에 서로 다른 식별자가 있으면 `AMBIGUOUS`, 명부에 없으면 `NOT_IN_SNAPSHOT`이다. 법인명 접미사 제거·약칭 추측·이름 부분 일치로 매핑하지 않는다.
- 회사 식별 근거에는 공시 번호, 원본/영수증 SHA, 조회 완료시각을 남긴다. 이는 출처가 보고한 기업 식별 정보이며 계약·납품·매출·수혜 증명이 아니다.
- 공개 원문을 다시 받지 않고 이미 허가된 본문 아카이브의 SHA/현재 권리를 확인한다. 본문은 결과 JSON에 포함하지 않는다.
- 비공개 결과는 `document_analysis/company_identity/article_company_identity_SHA.json`에 불변 저장한다. 동일 기사 버전은 조회 시 최신 결과 한 건으로 묶고 과거 시점 조회를 지원한다.

## 실행과 소비

```sh
python3 scripts/resolve_article_companies.py \
  --era-root /기존/EraLeader \
  --era-report /기존/official_api_pit_research.json \
  --independent-anchor /비공개/official_api_pit_research.pin.json \
  --archive-root /허가본문/archive --archive-version ARCHIVE_SHA \
  --receipt-sha256 RECEIPT_SHA --document-sha256 DOCUMENT_SHA \
  --registry /허가본문/registry.json
```

기존 대시보드의 **기사 속 기업 식별** 영역에서 회사명·기업 ID·공시 번호·시각·원문 링크·미확인 이름을 검색할 수 있다. 기사 집계나 신생 테마 수를 늘리는 기록으로 취급하지 않는다.

`search_news.py --company-identity-root /비공개/문서분석/company_identity --query 삼성전자`는 기존 뉴스 검색에 기업 식별 결과를 함께 제공한다. Python의 `search_article_identities(root, query=..., as_of=...)`는 읽기 전용이다.

기존 본문 예약 분석은 같은 분석 루트 아래의 식별 결과를 자동 읽어 원문 버전·본문 SHA·URL이 일치하는 경우 보고서에 결합한다. 경제 사건의 원문 회사명에만 ID를 연결하며 과거 사건 식별자는 보존한다. 식별 결과가 없거나 손상돼도 기존 뉴스·AI 분석은 계속한다. 신규 기사마다 명부 조회·결과 생성도 기존 본문 예약 처리에 연결했다. 아래 자동 생성 설정을 사용한다.

## 예약 자동 생성·캐시 (2026-10-15)

`run_motir_policy_once.py`와 `run_motir_document_analysis.py`는 `--company-identity-config`를 받는다. 기본값은 `~/Library/Application Support/NewsCatalystOS/company_identity.json`이다. 비공개 JSON의 세 필드는 `era_root`, `era_report`, `independent_anchor`이며 모두 기존 완료 스냅샷의 절대경로다. 기존 운영 스냅샷 경로로 설정 완료했으므로 설치된 MOTIR 예약 서비스의 다음 실행부터 적용된다. 별도 서비스나 기사별 등록은 없다.

본문 분석 전에 명부와 기사 원본을 읽고 자동 식별한다. v2 결과의 `directory_sha256`에는 명부의 원본·영수증 SHA와 기업 정보가 포함되고, 매번 달라지는 조회 시각은 제외된다. 같은 기사/명부/추출 규칙 버전은 `CACHE_HIT`, 변경은 `CREATED`로 새 불변 기록을 남긴다. 캐시에서도 원본 SHA·명부 pin·현재 기사 사용권을 확인한다. 과거 v1 결과는 읽기 호환한다.

설정 또는 명부 오류는 `UNAVAILABLE`로 기록하고 해당 실행에서 오래된 식별을 새 확인으로 붙이지 않는다. 뉴스 분석·다른 기사는 계속한다. 설정이 정상화되면 다음 실행에서 자동 복구한다. 설정이 없는 기존 호출은 저장된 식별 결과를 읽는 이전 동작을 유지한다.

실제 설치된 예약 인수를 사용한 replay 2회 모두 종료 0: 기사 172295·172292·172284는 첫 실행 `CREATED` 3건, 두 번째 `CACHE_HIT` 3건. 세 기사에서 식별된 회사명은 0개이며 빈 결과도 캐시된다. 기존 기사 171178의 삼성전자 식별은 보존했다. 두 실행 모두 새 수집·유료 AI 0건. 기존 테마 후보 수 1개 유지, 첫 실행 이력 버전 1개 추가 후 두 번째 버전 추가 0. 대시보드 HTTP 조회는 식별 기록 4개(v2 3개), 뉴스 43개, 테마 1개로 정상이다.

자동 생성·동일 명부 재조회·명부 갱신·기사 수정·권리 철회·명부 오류·복구·기존 분석/테마/HTTP를 포함한 변경 영향 테스트 **90 PASS / 0 FAIL**. 실제 신규 회사 식별 확대나 테마 정확도 향상 수치로 해석하지 않는다.


## 식별 이름의 사건 추출 연결
공시 명부에서 확인한 이름을 본문 선별 전에 넘겨, 특정 회사명 접미사가 없어도 실제 행동 문장에서 기업을 찾는다. 다른 문장의 회사는 가져오지 않는다. 이름 보강 전 원문 엔터티 목록을 `original_entity_ids`로 남겨 사건 ID와 과거 시점 결과를 유지한다. 기존 공급 관계 게시 경로는 이전의 이름 포함 사건 ID를 유지한다. 단순 명부 식별은 여전히 거래·수혜 증명이 아니다.
