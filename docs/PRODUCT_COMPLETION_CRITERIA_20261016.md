# NewsCatalystOS · EraLeader 개발 완료 조건

기준일: 2026-10-16 / 기준 ID: PRODUCT-COMPLETION-20261016

## 1. 적용 근거와 판정 범위

사용자가 두 프로젝트의 완료 조건 설명을 확인한 뒤 “명시해줘”라고 지시하여, 합의한 제품 목적·기능·운영·연동 조건을 이 문서로 통일한다. 완료 조건의 정의이며 현재 완료를 선언하거나 새 실행 증거를 만드는 문서가 아니다.

- **기능 완료:** 아래 해당 프로젝트의 사용자 기능이 구현되고 변경 영향 테스트를 통과한다.
- **실자료 확인:** 실제 허용 자료로 입력 → 처리 → 저장 → 사용자 출력이 이어지는 것을 확인한다. 합성 입력만 통과한 항목과 실제 자료의 결측 경로만 확인한 항목은 구분한다.
- **독립 운영 가능:** 해당 프로젝트의 기능·실자료 확인과 필수 운영 조건을 충족한다. 상대 프로젝트 연결 대기로 자체 운영을 막지 않는다.
- **통합 완료:** 두 프로젝트의 제품 기능과 필수 운영 조건에 더해 5절의 실제 연동 흐름이 확인된다. 독립 운영 가능과 통합 완료를 혼용하지 않는다.

기존 NewsCatalystOS 36개 세부 작업과 EraLeader의 기능 범위는 보존한다. 과거 36/36·약67%, 문서·테스트·커밋 개수만으로 현재 제품 목표를 완료 처리하지 않는다. NewsCatalystOS는 승인된 V1 반도체 범위부터, EraLeader는 한국·미국 시장 범위를 각각 평가한다. 임의 산업·시장 확대나 새 표본 수·정확도 수치·보유기간을 필수조건으로 추가하지 않는다.

### 필수조건에서 제외하거나 운영 후에 관찰하는 것

- 사람 검수자·수동 기사 승인·복수 사람 판정·500건 인적 라벨은 요구하지 않는다.
- NewsCatalystOS의 5거래일은 운영 후 안정성 관찰 목표이며 출시 전 대기 조건이 아니다. EraLeader에도 5거래일 사전 대기를 새로 추가하지 않는다. 실제 운영 기록은 사실대로 남긴다.
- 개별 미확보 자료, 별도 기관 인증, 새 표본 수·장기 성과 만기는 독립된 개발 전체의 중단 사유가 아니다.
- 수익 보장·목표 수익률 달성·자동매매·주문 실행은 두 프로젝트의 개발 완료 조건에 포함하지 않는다.

## 5. 두 프로젝트 공동 연동 완료 체크리스트

**뉴스 → 경제 변화/테마 → 관련 기업 → 사업·재무·가격·위험 평가 → 후보 비교 → 후속 변화 추적**을 실제 자료로 연결한다.

| ID | 완료 조건 | 확인할 출력 |
|---|---|---|
| INT-01 | 사건·테마 후보 전달 | NewsCatalystOS가 자기 영역에 발행한 버전 있는 연구 결과를 EraLeader가 읽어 정확한 기업·사건·테마·출처·시각을 유지한다. |
| INT-02 | 기업 평가 결과 연결 | EraLeader 평가 결과를 기존 기업 식별자로 연결하여 사용자 조회 경로에서 뉴스 근거와 사업·재무·가격·위험 평가를 함께 확인한다. 필요한 소비는 읽기 전용으로 수행하며 상대 DB·코드에 직접 쓰지 않는다. |
| INT-03 | 반복·정정·결측 처리 | 같은 판본 재소비는 중복을 만들지 않고 새 판본은 기존 이력을 보존한다. 잘못된 기업·미래 정보는 연결하지 않으며 한쪽 부재 시 다른 쪽의 정상 기능은 계속된다. |
| INT-04 | 실제 끝까지 실행 | 실제 사건/테마와 기업 평가가 사용자 화면·보고까지 이어지는 증거가 있다. 합성 계약 테스트만으로 실연동 완료를 선언하지 않는다. 기준일·자료 범위·소스 버전과 두 코드 SHA를 함께 기록한다. |

이 연동은 연구 데이터 교환이며 전략 수신자 지정·주문·계좌·배분 명령을 포함하지 않는다. DART/KRX/SEC 수집기를 중복 개발하지 않는다. 실제 연동 미완료는 통합 완료를 막지만 각 프로젝트의 독립 운영 시작을 막지 않는다.

- 이 기준은 각 프로젝트 docs/PRODUCT_COMPLETION_CRITERIA_20261016.md에 같은 내용으로 보관한다. 추후 사용자 결정으로 공동 기준을 바꾸면 양쪽을 함께 갱신한다. 기록 자체를 새 권한·외부 설치·전송 승인으로 해석하지 않는다.
