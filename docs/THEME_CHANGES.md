# 기간 전후 테마 변화 조회

`/api/theme-changes?since=<ISO시각>&as_of=<ISO시각>&q=<검색어>&activity=all`은 `newscatalyst.theme_changes.v1`을 반환한다. since는 필수이며 종료 시각을 생략하면 현재 시각이다. UTC 또는 시간대가 있는 시각을 사용한다. 역전/미래 종료 시점은 거부한다.

CLI 예시(합성 날짜):

```sh
python3 scripts/search_themes.py --changes --since 2026-10-15T00:00:00+09:00 --as-of 2026-10-16T00:00:00+09:00 --query 액침냉각
```

`--root`는 기존 테마 저장 경로, `--export-root`는 선택적인 소유자 전용 JSON 저장 경로다. `--changes`는 기업/재무 출력 옵션과 별도 모드다. 기존 출력과 소비 계약은 변경하지 않는다. activity는 all/changed/new/updated를 재사용한다.

ThemeStore.period_versions는 동일 읽기 전용 연결에서 시작 직전(`< since`) 최신 판본 하나와 종료까지(`<= as_of`)의 기간 내 판본들을 반환한다. 각각 저장 SHA·메타데이터를 확인하고 기존 bundle 검사로 가용시각을 확인한다. 한 번도 없던 테마는 before=null, 새 판본이 없으면 unchanged다. 조회는 DB를 생성하거나 수정하지 않는다.

각 ThemeChanges 항목에는 양끝 판본의 SHA/시각/상태/점수, 활성 사건의 추가·제외, 기업의 추가·제외/식별 변경, 출처 판본 추가·제외, 상태 전이와 근거가 있다. source_available_at은 출처 가용 시각, recorded_at은 이 테마에 기록된 시각이다. 늦게 확보한 과거 기사를 과거 판본에 소급하지 않는다.

사건별 action_group_id는 기존 계획/개시 쌍을 양끝에서 한 행동으로 비교하기 위한 파생 식별이다. events의 독립 행동 수는 양끝 활성 집합의 변화이며 기간 중 총 발표 건수가 아니다. 기간 안에 처음 관측됐다가 철회된 사건은 양끝 추가0일 수 있어도 status_transitions와 sources에 경과가 남는다. 같은 사건 재보도는 출처 추가, 기존 문서/사건의 이름→코드 변경은 identity_updates, 기존 사건의 기업 보완·공급 관계는 기업 문맥으로 표시한다. 이런 변화는 새로운 경제 행동이나 기업 확산을 뜻하지 않는다.

대시보드의 ‘이 기간 달라진 근거’는 원문 링크와 시각, 기업 변화, 상태 전이를 보여 준다. 비교 오류는 기존 뉴스·테마 표시를 숨기지 않는다. 미래 날짜는 아직 시작되지 않은 기간으로 다룬다. 출처 보도와 테마 연결은 가설이며 실제 거래·매출·수혜 또는 시장 주도성을 인증하지 않는다.
