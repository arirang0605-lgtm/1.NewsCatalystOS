# 테마와 반도체 공급망 연결

## 구현된 경로

완료 게시된 기존 공급망 그래프(v1 공시 / v2 기업 IR·정부 문서)를 고정 SHA로 읽는다. 기존 소비기의 게시 완료·출처·시점 검사를 재사용하며 원본과 EraLeader에는 쓰지 않는다. 테마 저장소에 근거를 한 번 등록하면 이미 저장된 사건과 이후 들어오는 사건에 자동 연결한다. 사람 검수·기사별 승인·추가 AI 호출은 없다.

연결 조건은 모두 일치해야 한다.

- 경제 관측의 `source_binding.source_event_sha256` = 그래프의 `event_sha256`
- `source_binding.document_sha256` = 관계 근거의 원문 SHA
- 관측 산업에 `SEMICONDUCTOR` 포함
- 관측 `entity_ids`에 그래프 공급자 또는 고객의 `namespace:company_id` 포함 (예: `SEC_CIK:111111`)

기업 이름만 같거나 반도체라는 이유만으로 연결하지 않는다. 같은 문서·기업의 관계 문맥을 연결하며, 그 계약이 해당 경제 사건을 발생시켰다는 인과관계를 확정하지 않는다. 공급망으로 추가된 기업을 독립 사건·테마 기업 폭 점수에 더하지 않는다.

## 표시와 이력

- `REPORTED_DIRECT_TRANSACTION`: 출처에 보고된 직접 계약. 실거래·실매출 확정은 아니다.
- `ANNOUNCED_SUPPLY_PLAN`: 공급 계획. 계약 이행으로 승격하지 않는다.
- `impact_category`: 기존 반도체 전파 모듈의 잠재 수혜/피해 또는 영향 미확인. 고객에게 공급자의 수혜 판정을 복사하지 않는다.
- 근거 없는 기존 기업 연결: `THEMATIC_ONLY` 유지.
- 공정, 공급자/고객 역할, 상대 기업 ID, 출처 링크, 근거 가용시각, 연결시각과 상충 보도를 검색·대시보드에 표시한다.
- 공식 철회로 무효화된 사건의 현재 관계는 제거하고 과거 버전은 보존한다. 일반적인 후속 사건 처리에서도 등록된 근거를 유지한다.

공급망이 연결된 후보/출력은 각각 `newscatalyst.theme_candidate.v2`, `newscatalyst.theme_delivery.v2`다. 기존 v1 저장·출력은 계속 읽는다. 출력에는 원문 없이 SHA로 고정된 기존 그래프 메타데이터와 연결 내역을 담고, 소비 시 관계 표시를 다시 계산해 검사한다.

## 실행

기존 `publish_reviewed_beneficiaries.py`에 `--theme-root /비공개/theme_history`를 지정하면 게시 후 자동 등록한다. 테마 목적지 오류는 이미 완료된 공급망 게시를 취소하지 않으며 `theme_link_status=UNAVAILABLE`을 표시한다. 같은 게시물을 아래 명령으로 재처리할 수 있다.

```sh
python3 scripts/connect_theme_supply_chain.py \
  --folder /비공개/outbox/reviewed_candidate_SHA \
  --out-root /비공개/outbox --expected-sha256 SHA \
  --graph-version v2 --root /비공개/theme_history
```

정규화 경제 관측은 기존 `run_theme_discovery.py`를 사용한다. `economic_observation(..., source_binding={...})`으로 위 원문 결합을 선택적으로 제공한다. 산업부 본문 자동 분석은 아카이브 버전/본문 SHA를 관측에 기록한다. 아직 이름만 있는 기업을 임의의 법인 ID로 치환하지 않는다.

## 회사명 → 기업 ID 자동 연결

`publisher_theme_events.py`가 기존 허가 원문과 같은 입력에서 확인된 공급자/고객 `CompanyBinding`을 재사용한다. 게시 CLI의 `--theme-root`를 설정하면 원문 경제 변화 추출 → 같은 문단의 회사명 → 기업 ID → 테마 및 공급망 연결까지 수행한다. RSS 주소를 원문 주소로 표시하지 않으며 현재 직접 원문 주소가 확인되는 DOCUMENT 입력에 적용한다. 기존 공급망 게시만 사용할 때는 이 추출을 실행하지 않는다.

- 원문에 쓰인 이름과 바인딩을 같은 자료에서 한 번 읽어 검사한다. 다른 문서의 동명 기업, 부분 문자열, 추측한 약칭은 연결하지 않는다. 대소문자·유니코드·연속 공백만 정규화한다.
- 관측 `company_mappings`에 원문 이름, 기업 ID, 식별 근거 SHA를 남긴다. 미확인 이름은 그대로 유지한다. 원문 문장 자체는 테마/출력에 저장하지 않는다.
- 사건 식별자는 원문 이름을 기준으로 유지한다. 후속 기업 식별로 기업 ID가 추가되어도 기존 사건 수가 두 배가 되지 않으며 과거 버전에는 나중 식별자를 소급하지 않는다.
- 검색은 원문 회사명과 기업 ID를 모두 지원하고 대시보드는 이름과 ID를 함께 표시한다. 공급 계획은 계획으로 유지하며 기존 기사에서 새 경제 행동이 없으면 새 사건을 만들지 않는다.

## 확인 범위 / 다음 작업

전체 회귀 1,106개 통과. 이후 기존 공급망 단독 호출의 호환성을 위한 선택 실행 조정 후 관련 55개 통과. 새 회사명 연결 테스트 15개에는 원문→게시→테마→공급망→검색/JSON 정상 경로, 부분 이름, 문단 분리, 과거 기사, 계획, 미래/권리/다른 문서 입력, PIT 이력이 포함된다. 회사명 연결 정상 경로는 합성자료다.

실제 산업부 171178 보관 원문은 기존 경제 사건 추출 0건이며 ASML·삼성전자/SK하이닉스 공급 보도 후보의 `company_ids_verified=false`를 유지했다. 임의 ID나 신규 사건을 생성하지 않았다. 현재 두 예약 서비스의 최근 결과는 정상이며 기존 AI 비용 원장 성공 정산 3건 5.1798원(설정 단가 추정), 미정산 예약 포함 12.7574원이다. 이번 호출 비용 0원. 기존 비용/캐시 복원본 SQLite 무결성은 모두 ok다.

다음은 이미 게시 완료된 읽기 전용 공시/기업 명부의 이름·법인코드 자료를 기존 `official_filing_context` 경로로 소비해 실제 기사 기업 식별 입력을 확보하는 것이다. 기존 원문 회사명과 별칭의 연결 근거가 있어야 하며 미확인을 임의 해소하지 않는다. 사람 검수·추가 승인 절차를 만들지 않는다.
